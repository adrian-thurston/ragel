Colm is distributed in the Colm Suite, along with the Ragel State Machine
Compiler. Suite releases are named for the year and month they were made, and
the components in them carry their own version numbers. Release
{suite-release} contains colm {colm-version}.

== Getting the source

The releases are listed on the https://www.colm.net/open-source/colm/[colm page]
at colm.net, each with a PGP signature and a SHA-256 checksum.

[source,bash,subs="attributes+"]
----
wget https://www.colm.net/files/colm-suite/{suite-release}/colm-suite-{suite-release}.tar.gz
wget https://www.colm.net/files/colm-suite/{suite-release}/colm-suite-{suite-release}.tar.gz.sha256
sha256sum -c colm-suite-{suite-release}.tar.gz.sha256
----

The checksum shows the download is intact. To check who made it as well,
verify the release's signature against the key colm.net publishes:

[source,bash,subs="attributes+"]
----
wget https://www.colm.net/files/colm-suite/{suite-release}/colm-suite-{suite-release}.tar.gz.asc
wget https://www.colm.net/files/thurston.asc
gpg --import thurston.asc
gpg --verify colm-suite-{suite-release}.tar.gz.asc colm-suite-{suite-release}.tar.gz
----

gpg should report a good signature from Adrian Thurston, made with the key that
has this fingerprint:

----
C326 0F00 1EE3 780F 1BC3  D4F6 50FE 4727 7DC1 96FB
----

The key comes from colm.net, as the release does, so compare its fingerprint with
a copy from somewhere else, such as https://keyserver.ubuntu.com/[the Ubuntu
keyserver]. Until you certify the key, gpg also warns that it is not certified
with a trusted signature. Comparing the fingerprint is the check that warning
asks for.

Then unpack the release:

[source,bash,subs="attributes+"]
----
tar -xzf colm-suite-{suite-release}.tar.gz
cd colm-suite-{suite-release}
----

The development sources are on
https://github.com/adrian-thurston/colm-suite[GitHub]. A git checkout has no
`configure` script: run `./autogen.sh` first, which needs autoconf, automake and
libtool.

== Building with autotools

The build needs make, gcc and g++.

[source,bash]
----
./configure --prefix=/opt/colm
make
sudo make install
----

This installs colm and ragel under `/opt/colm`.

Without `--prefix`, the suite installs under `/usr/local`. On Debian, Ubuntu and
other systems that list `/usr/local/lib` in their loader configuration, run
`sudo ldconfig` after `sudo make install`, or colm won't start. The
xref:9_00_q_and_a.adoc#libcolm-not-found[FAQ] explains why.

To install colm but not ragel, configure with `--disable-install-ragel`:

[source,bash]
----
./configure --prefix=/opt/colm --disable-install-ragel
----

The whole suite is still built; only the install leaves ragel out. The README's
https://github.com/adrian-thurston/colm-suite#installing-one-half-of-the-suite[Installing
one half of the suite] has the details.

== Building with CMake

CMake 3.16 or later can build the suite instead. Only out-of-source builds are
supported.

[source,bash]
----
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DCMAKE_INSTALL_PREFIX=/opt/colm
cmake --build build -j$(nproc)
sudo cmake --install build
----

To install colm but not ragel, add `-DCOLM_INSTALL_RAGEL=OFF` to the first
command.

A colm built by CMake always looks for its headers and runtime library where it
is installed, so install it before using it to compile colm programs. The test
suite builds only with autotools. The README's
https://github.com/adrian-thurston/colm-suite#building-with-cmake[Building with
CMake] lists the options and the other differences from the autotools build.

== Running colm

Either build above installs colm in `/opt/colm/bin`. Put that directory on your
`PATH`, and check that colm runs:

[source,bash]
----
export PATH=/opt/colm/bin:$PATH
colm --version
----

The first line it prints is:

[subs="attributes+"]
----
Colm version {colm-version} {colm-pubdate}
----

Colm compiles a program to C, then compiles the C with gcc, against the colm
headers and the colm runtime library, libcolm, that were installed with it. So
colm needs a C compiler wherever it is used, not only where it is built. It runs
`gcc`, or the compiler named by the `CC` environment variable, and passes it
`CFLAGS` from the environment as well.

[source,chapel]
.hello_world.lm
----
include::code/hello_world.lm[]
----

[source,bash]
----
colm hello_world.lm
./hello_world
----

----
include::code/hello_world.exp[]
----

`colm hello_world.lm` writes the C program to `hello_world.c` and the executable
to `hello_world`. With `-r`, colm also runs the executable once it is built. The
program reads colm's standard input and gets no arguments.

[source,bash]
----
colm -r hello_world.lm
----

The executable needs libcolm when it runs. After an autotools install, colm
links it against the shared library and records the install's library directory
in it, so it runs on the machine colm is installed on. To run it on another
machine, install the same colm release there, under the same prefix. CMake
builds libcolm as a static library by default, and then the executable contains
the runtime.

== Further reading

The ideas behind colm, in particular its parsing method, are set out in Adrian
Thurston's https://www.colm.net/files/colm/thurston-phdthesis.pdf[Ph.D. thesis].
It is not a manual, and the language has changed since it was written.
