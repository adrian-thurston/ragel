[[structs]]
== Structs

A struct groups named fields. `struct Name`, then its fields, each
`Name: Type`, then `end`, defines one:

[source,colm]
----
struct point
	X: int
	Y: int
end
----

A field can't have a first value: that is a parse error.

`new Name()` makes a struct, with its fields at 0, false or nil.
`new P: Name()` also declares `P`. `+P->Field+` reads or sets a field.
`P.Field` is an error, `dot cannot be used to access a pointer`.

A struct variable is nil until it is given a struct, so make one with `new`
before using its fields. Reading or setting a field of a nil struct stops the
program, as xref:8_04_error_handling.adoc#run-time-errors[the error handling
chapter] says. A field can hold a struct of the same type.

Structs are shared, as xref:2_00_types.adoc#sharing[the types chapter] says,
so a function can change a struct passed to it.

A struct can also hold `lex` blocks, tokens and defs. Passed to `parse`, it
is a parsing context, the subject of xref:3_04_undo.adoc#context[the context
chapter]. `context` is another keyword for `struct`.

[[aliases]]
== Aliases

`alias Name Type` gives `Type` a second name. The two names are one type, and
a value of either can be assigned to a variable of the other. An `alias` goes
at the top level, in a struct or in a namespace. In a function, it is a parse
error. `poker`, above, uses `alias` for its maps and lists, and `type_share`,
in xref:2_00_types.adoc#sharing[the types chapter], for a list.

[[lists]]
== Lists

`list<T>` holds values of type `T`, in order. `new list<T>()` makes an empty
one. A list's functions and fields are reached with `+->+`, as a struct's
are.

* `push_tail( V )` and `push_head( V )` add a value at the tail or the head.
  `push( V )` is `push_head( V )`.
* `pop_head()` and `pop_tail()` take a value off the head or the tail, and
  give it back. `pop()` is `pop_head()`. Popping an empty or nil list stops
  the program, as xref:8_04_error_handling.adoc#run-time-errors[the error
  handling chapter] says.
* `length` is the number of values.
* `for V: T in L` gives the values from head to tail, and
  `for V: T in rev_list_iter( L )` from tail to head.
* `head` and `tail` are the values at the head and the tail, and `top` is
  `head`. Reading one on an empty or nil list stops the program too.
* `head_el` and `tail_el` are the first and last elements, each a
  `list_el<T>`. An element's `value` is its value, and its `next` and `prev`
  are the elements beside it, nil at the ends. On an empty list, `head_el`
  and `tail_el` are nil. Reading or setting a nil element's `value`, or
  reading its `next` or `prev`, stops the program. `for E: list_el<T> in L`
  gives the elements.

A list can't change inside a `for` over it: that is a compile error,
`reference active, cannot write to object`.

A list variable is nil until it is given a list, with `new`. Calling one of
a nil list's functions or reading one of its fields stops the program, and so
does a `for` over it, as a loop over a nil tree does
(xref:1_06_iterators.adoc#iterators[the iterators chapter]). A push prints
`fatal: push to a nil list`, a `for` prints `fatal: for loop over a nil list`,
and the program exits with status 1.

`argv` is a `list<str>`, as xref:1_00_language_overview.adoc#exit[the
language overview] shows.

[[maps]]
== Maps

`map<K, V>` maps keys of type `K` to values of type `V`. `new map<K, V>()`
makes an empty one. Its functions and fields are reached with `+->+` too.

* `insert( K, V )` adds the key `K` with the value `V`. If the key is there
  already, the map keeps its old value.
* `find( K )` gives the key's value. When the key isn't there, it gives 0 for
  an `int` value, and nil for a `str`. `find_el( K )` gives the key's
  element, a `map_el<K, V>`, or nil.
* An element's `key` and `value` read them, and setting `value` changes the
  map. Reading or setting them on a nil element, such as `find_el` gives for
  a missing key, stops the program, and so does reading its `next` or `prev`.
* `remove( K )` takes the key out, and gives its element, or nil if it wasn't
  there.
* `length` is the number of keys.
* `for V: ValueType in M` gives the values, and `for E: map_el<K, V> in M`
  the elements, in key order. `head_el` and `tail_el` are the first and last
  elements, and an element's `next` and `prev` walk the same order.

Int keys go from low to high, negative ones first. Str keys go by length
first, then byte by byte, as xref:1_02_expressions.adoc#operators[the
expressions chapter] says.

A map can't change inside a `for` over it.

A map variable is nil until it is given a map, with `new`. Calling one of a
nil map's functions, reading one of its fields or a `for` over it stops the
program the same way. An `insert` prints `fatal: insert into a nil map`, a
`for` prints `fatal: for loop over a nil map`, and the program exits with
status 1.
