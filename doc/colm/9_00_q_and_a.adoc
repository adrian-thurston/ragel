== FAQ

[[libcolm-not-found]]
.Q: colm won't start, with this error
[subs="attributes+"]
----
colm: error while loading shared libraries: libcolm-{colm-version}.so: cannot open shared object file: No such file or directory
----

*A*: Run `sudo ldconfig`.

This happens after an autotools install under `/usr/local`, the default prefix,
on Debian, Ubuntu and other systems that list `/usr/local/lib` in their loader
configuration, `/etc/ld.so.conf`. The colm program is linked against the shared
colm runtime library, libcolm. Libtool doesn't record a library directory in the
programs it installs when the loader configuration already lists it, so the
loader looks for libcolm in its cache, `/etc/ld.so.cache`. `make install`
doesn't update the cache, and `ldconfig` does:

[source,bash]
----
sudo make install
sudo ldconfig
----

Run it again after installing a new version of colm, since the library's name
carries colm's version. Ragel, installed with colm, fails the same way, naming
one of the suite's libraries, and `ldconfig` fixes it too.

Other cases don't need this step:

* With a prefix whose library directory the loader configuration doesn't list,
  such as `/opt/colm`, libtool records that directory in the colm program, which
  finds libcolm there.
* CMake builds libcolm as a static library by default, so colm doesn't load it
  at all.
* The programs colm compiles are linked with `-Wl,-rpath` to the install's
  library directory, so they find the shared libcolm without the loader's cache.
